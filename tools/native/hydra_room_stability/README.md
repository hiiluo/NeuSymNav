# Private Hydra RoomFinder stability policy

This opt-in build copies the pinned Hydra `room_finder.cpp`, compiles that one translation unit with the existing CMake flags and relinks the existing Hydra objects into a private `libhydra.so`. It does not alter installed Hydra, headers, class layout, source repository or defaults. From the worktree root run `python3 tools/native/hydra_room_stability/build.py`; the output, commands and log are under `runs/hydra-objectnav/B1-stability-20261107/native/`. The runtime must load that exact DSO before Hydra bindings, verify its SHA and loaded library identity, and configure before constructing a pipeline.

ABI exports `nsn_room_stability_version()`, `nsn_room_stability_configure(const char*)` and `nsn_room_stability_last_decision()`. Version is `neusymnav-room-stability-v1`. Configuration JSON is `{"enabled":true,"confirm_observations":3,"candidate_tolerance_m":0.02,"numerical_epsilon_m":0.0001}`; disabled is the default. Configure returns zero on success; invalid options return 1, and a configuration attempt while instances have registered state returns 2. Diagnostic strings are thread-local copies and valid until the next call on that thread. Diagnostics are a process-wide latest decision, not a per-pipeline event ledger; the integration must serialize the intended single worker pipeline.

Every call computes native candidate filtration and current seed support. Bootstrap accepts the first supported candidate. A threshold differing by at most 0.0001m follows the current raw event. Otherwise three strictly increasing nonzero maxima of current place `last_update_time_ns` with thresholds within 0.02m of the pending candidate permit adoption. That timestamp is a graph-update proxy, not proof of independent sensor viewpoints; graph changes with a non-increasing maximum cannot advance confirmation. During a hold the old level is snapped only to a current filtration event within 0.0001m; components are always recomputed from current graph. If held components have no usable support, valid raw components replace them immediately and reset pending state. Missing filtration window, raw candidate or raw support is unavailable, resets the pending streak, and advances a nonzero increasing timestamp watermark; it never returns old memberships. Destructor removes per-instance state. This is threshold stabilization, not room identity, lifecycle confirmation, navigation safety, or a guarantee of semantic correctness.

`python3 tools/native/hydra_room_stability/test_build.py` builds the native fixture driver; run `runs/hydra-objectnav/B1-stability-20261107/native/test_native`. The synthetic graph exercises one-frame spike, duplicate timestamp, sustained transition, current seed merge/split, vanished held support and destructor reset. `test_api.py` checks the C ABI against the private library when dependency search paths are configured. Real episode replay and disabled equivalence require independent integration checks; synthetic evidence is not runtime validation.
