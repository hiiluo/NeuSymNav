# Private Hydra GVD trace probe

Build from the existing Hydra build tree: `python3 tools/native/gvd_trace_probe/build.py`. It reads source/flags/link command, copies the source to the artifact directory, adds observation hooks, compiles one translation unit and links a private `libhydra.so` against the existing objects. It does not edit or relink the installed library. Commands, logs, exit codes and SHA-256 fingerprints are written to `runs/hydra-objectnav/B1-support-20261107/native-probe/`. The generated source is the exact executable instrumentation; anchor counts are asserted before editing. Requires the existing branch-specific build paths and toolchain.

For a child process, use `tools/native/gvd_trace_probe/setup.sh` in place of `.runtime/hydra_ws/env.sh`, set `NEUSYMNAV_GVD_PROBE_LIBDIR` to the absolute artifact directory and `HYDRA_GVD_TRACE_JSONL` to an absolute output file. The setup sources the ordinary environment first, then prepends the private library. `loader.txt` records `/proc/self/maps` after importing the native binding. Always verify the actual child loader and ensure a new trace file is produced; an inaccessible trace path disables logging silently. Output appends, so use one fresh file per process/run. No tracing is enabled without the path environment variable.

One `begin`/`end` pair per `extract(timestamp_ns)` brackets each extract. `updated_gvd` is emitted during `updateGvdGraph` after its 26-neighbor scan, before isolated deletion or clearance compression; its `isolated_at_visit` reflects that precise iteration and may change as neighbors are processed. Zero-basis modified voxels are rejected earlier by `fillSeenVoxels` and are not GVD nodes; these are not logged. `gvd` snapshots enumerate the actual full surviving GVD graph, including below-clearance nodes, adjacency and current compression remapping. The snapshots occur after `assignCompressedNodeAttributes`/`updateCompressedEdges` (`before_merge`), immediately after optional `mergeNearbyNodes` (`after_merge`), and after optional heuristic edges and validation (`final`). Each `compressed` record includes actual active/archived GVD refs, best representative, siblings, graph state, and representative geometry/clearance/basis if the best GVD is present. `place` records show actual graph attributes and adjacency, including archived graph nodes. `merge` records are the final resolved from/to pairs immediately before the actual graph merge. IDs are local to one extractor episode, and timestamps are simulator inputs, not guaranteed globally unique revision identifiers. Sequential begin/end order provides an extraction ordinal; join input identity using the replay's timestamp provenance.

Important: nearby merging sets the losing compressed entry `in_graph=false` and merges graph nodes; it does not merge the compressed membership sets. Treat recorded pairs as the graph remapping for that extraction; do not assume `compressed_remapping_` changes. Archives/deletions and later reactivation can change history. `gvd` snapshots are after isolated deletion, hence use `updated_gvd` for those rejected at visitation. Whole-graph output preserves support outside the ROI and edges, at the expense of disk and processing time; it is an offline diagnostic only.

Build and loader success do not prove behavioral parity. Before analysis compare the same accepted prefix and final native places/edges/room output with an original-library run, and verify every JSONL record parses, begin/end pairs close, snapshot stages and actual merge records are present when expected. This probe has not independently passed that replay gate as of its build.
