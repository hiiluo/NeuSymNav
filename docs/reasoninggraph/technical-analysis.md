## Sơ đồ tính toán và giới hạn

Trong phân tích độ phức tạp, `d` là chiều CLIP, `H×W` là kích thước RGB-D, `N` là số instance hợp lệ, `m` là số instance được chọn cho VLM, `V` là số vertex active, `C` là số cluster active, `A` là số object node active, `O` là tổng số object, `E` là số edge pair, `F` là số embedding frame lịch sử, `K` là số room centroids, `Q` là số text query. Đây là chi phí suy ra từ loop và payload, không phải benchmark.

### 1. Graph và dữ liệu vào

Bài báo dùng $\mathcal G=\langle\mathcal N,\mathcal E\rangle$, $\mathcal N=\bigcup_{\ell=1}^{5}\mathcal N_\ell$ và $\mathcal E=\bigcup_\ell\mathcal E_{\ell,\ell}\cup\bigcup_{\ell<5}\mathcal E_{\ell,\ell+1}$. Năm tầng là metric-semantic mesh, object, place, room và building. Mesh vertex có xyz/RGB/semantic label. Object giữ centroid, bbox, label, feature và count. Place và room nối bằng membership. Object–object mang relational evidence. TSDF/ESDF và marching cubes tạo mesh. Clustering Euclidean theo label tạo object. GVD sparsification tạo places. Room detection cắt place graph. Mesh connections biểu diễn vertex membership. Hydra còn có dynamic agent layer lưu pose. Chi phí lưu phần khung là $O(V+\sum n_\ell+\sum e_\ell)$ ngoài voxel map và feature buffers. [Bài báo §§III, IV-A][paper] · [Frontend][frontend] · [Mesh clustering][mesh] · [GVD][gvd] · [Room finder][room-finder]

ROS bridge dùng `ApproximateTime` cho RGB, depth, panoptic, frame feature, semantic feature image và relations. `ImageReceiver` nhận intrinsics/distortion từ CameraInfo, đổi depth uint16 mm sang float32 m, giữ RGB stamp làm timestamp packet, remap ảnh/depth, rồi đưa panoptic mask `uint16[H,W]`, map feature theo panoptic ID và map cặp sang reconstruction. ROS graph pipeline đọc odometry qua TF/pose graph. Việc các topic đến gần nhau về thời gian là semantics pipeline gốc. NeuSymNav dùng khóa frame và calibration provenance theo hợp đồng Habitat để gắn evidence và giữ control độc lập. [ROS launch][robot] · [Receiver][receiver] · [Sync policy][sync]

### 2. Object feature theo observation

Eq. 3 dùng $f_i=\alpha_m C_I(M_i\odot I)+\alpha_b C_I(\operatorname{crop}(I,B_i))+\alpha_t C_T(s_i)$ với tổng ba trọng số bằng 1. Masked patch đặt background đen và lấy patch theo bbox. Code dùng `ConstantMask(-mean/std)` để giá trị pixel sau normalization tương ứng màu đen. `OpensetSegmenter.encode` lọc vocabulary và mean depth nếu depth được cung cấp, trích patch, lấy mẫu ngẫu nhiên khi quá `max_batch`, pad batch thiếu, rồi encode. Nhánh sparse dùng weights trực tiếp. Bbox branch luôn chạy encoder cùng ảnh đầy đủ, và giá trị vào object mean là bbox output nhân weight. Các wrapper CLIP trả projection trực tiếp. Cosine ở retrieval tự chia norms. Có một đường `CLIPFeaturesExtractor.encode` riêng lấy trung bình đều trên modalities được bật, vì vậy cần kiểm tra launch trước khi đối chiếu. [Alg. 1 và Eq. 3][paper] · [Sparse path][openset] · [Patch][patch] · [Separate extractor][clip-only] · [Wrappers][wrappers]

Bản YAML open-set robot dùng YOLOe confidence 0,4, IoU 0,85, size 640 và OpenCLIP ViT-B-32 `laion2b_s34b_b79k`, `max_batch=10`, text/mask/bbox weights lần lượt 0,9/0,1/0,0, depth 0,05–7 m. Paper §V-A nêu OpenAI ViT-L/14. Cấu hình ViT-B-32 cho patch `[b,3,224,224]`, text token length 77, object features `[b,512]` và frame feature `[512]`. Nếu không còn object sau lọc, đường encode trả `image_embedding=None` trước khi chạy full-frame CLIP. Chi phí feature loại sparse xấp xỉ $O(b\,C_I+b\,C_T)$ sau detector, với batch padded và crop tạm. Tổng masks có thể chiếm $O(NHW)$ và store object $O(Od)$. [YAML][openset-config] · [Robot launch][robot] · [ViT-B-32 config](https://github.com/mlfoundations/open_clip/blob/v2.29.0/src/open_clip/model_configs/ViT-B-32.json) · [Segmenter][openset]

### 3. Object fusion qua snapshot mesh

Alg. 2 và Eq. 4 tập hợp $m_i=|S_i|^{-1}\sum_{v\in S_i}f_v$ trên tập vertex có feature rồi cập nhật $\bar f_i'=(n_i\bar f_i+m_i)/(n_i+1)$. Count ở object tăng theo lần nhận **cluster feature**, không bằng số camera frame, pixel hay vertex. `MLESemanticIntegrator` còn có fusion mean ở semantic voxel và cập nhật semantic likelihood/label. Marching cubes nội suy vector khi cả hai endpoint có feature, dùng endpoint có feature khi chỉ một đầu hợp lệ. `findClusters` tính trung bình các vector hợp lệ và chọn panoptic ID theo số vote vertex. `updateGraph` tìm active node cùng label theo geometry overlap, tạo node nếu thiếu, sau đó merge active nodes. `updateObjectSemanticFeature` khởi tạo ở count 1, bỏ qua khi cluster thiếu feature. `mergeObjectSemanticFeature` gộp hai mean theo count. Nhánh gọi merge trong `mergeActiveNodes` phụ thuộc cluster hiện tại có feature. [Bài báo][paper] · [Voxel][sem-voxel] · [Marching cubes][marching] · [Cluster aggregation][mesh] · [Means][utils]

`ReconstructionModule::clearSemanticFeatures` dọn feature/ID ở block cập nhật sau xuất mesh, và frontend dọn bản sao trong mesh delta. Clear voxel reset feature và panoptic ID. Hàm giữ `num_observations`, khiến cửa sổ count và vòng đời feature cần phân biệt khi đối chiếu. Việc quét/aggregate vector có chi phí $O(Vd)$, bộ nhớ transient worst case $O(Vd)$ ở mesh (cộng voxel copy). Euclidean clustering dùng PCL KdTree theo label, worst case nhiều neighborhood dày có thể tới $O(V^2)$. Matching cluster quét active nodes trong label và merge active nodes có loop cặp. Với NeuSymNav, phép merge sidecar dùng sums/counts của evidence đã deduplicate, và canonical ID chỉ đến từ native lifecycle authority của profile Hydra. Phép so sánh direct observation với mesh assignment là một ablation riêng. [Clear upstream][recon] · [Frontend][frontend] · [Matching][mesh]

### 4. Room feature và retrieval

Alg. 3 đưa $C_I(I_t)$ vào bucket của room chứa pose $x_t$, sau đó lưu $\min(F_r,K)$ vectors trên room. Bản phát hành đặt frame feature vào AGENT node cuối của dynamic layer đầu, rồi gom lại các `AgentNodeAttributes.image_feature` theo parent AGENT → place → room sau rewrite room graph. `computeRoomFeatures` skip khi thiếu feature/kmeans/agent. Dữ liệu giữ mọi frame feature được attach để gom lại, đồng thời giữ summary `RoomNodeAttributes.feature_vectors`. Config robot đặt `K=10`, tối đa 100 vòng, tolerance $10^{-4}$. `KMeans` khởi tạo centroids ngẫu nhiên bằng `random_device`. Assignment dùng negative cosine, update lấy mean Euclidean của vector được gán, giữ centroid cũ nếu cluster rỗng. Nếu số observation ≤K, lưu raw vectors. Khi tái grouping, chi phí $O(Fd+\sum_r I_r F_r Kd)$ và lưu persistent $O(Fd+RKd)$, với $R$ là số room và $I_r$ số vòng của room r. [Alg. 3][paper] · [Room update][rooms] · [KMeans][kmeans] · [Config][room-config] · [Serialization][spark-node]

Bài báo §IV-C tính score room bằng trung bình $K\times Q$: $s_r=(K_r Q)^{-1}\sum_{k=1}^{K_r}\sum_{q=1}^Q \cos(f_{rk},t_q)$. Robot YAML dùng max, không softmax, threshold 0,15. `searchRooms` hiện dùng `text_room_embeddings[i]` với i là room index, loop trong chạy j qua centroids. Như vậy bỏ mất vòng Q và có thể truy cập ngoài bounds nếu số room vượt số query. `searchRoom` dùng một text embedding nhưng nhánh mean/max thiếu guard khi room không có centroid. Chọn công thức paper hoặc score single-query rõ ràng, loại room rỗng, kiểm tra nhiều rooms với Q=1 và room revision khi port. Paper score có chi phí $O(RKQd)$. [Room search][cos] · [Object search routing][search] · [Robot thresholds][search-config]

### 5. Pair extraction và hợp đồng tensor

Alg. 1 bước 8 mô tả detector pairs có thứ tự $i\ne j$. Crop là **hình chữ nhật bao** hai bbox. Bản phát hành tái tạo masks từ semantic/panoptic image, lọc class/area/depth. `torch.combinations` tạo cặp không thứ tự trên subset đã chọn. `include_bbs` vẽ hai outline mang màu của label rồi crop union cộng 20 px clipped vào frame. `full_img` cho phép chia sẻ một feature ảnh cho nhiều pairs qua receiver. VLM YAML port công khai đặt `max_batch_vlm=2`, area >300 px², depth 0,1–7 m, `full_img=false`, `include_bbs=true`, `use_graph_edges=false`, extractor mặc định InstructBLIP Vicuna-7B visual. Vì vậy cap thông thường là một pair/frame với config đó. Nhánh graph-aware, khi bật, dùng $P_{world}=T_{world\leftarrow cam}(\bar z K^{-1}(\bar u,\bar v,1)^T)$ để thử containment trong bbox 3D gần, ưu tiên detection có degree nhỏ rồi lấy thêm ngẫu nhiên. Vẫn encode mọi combination của subset. Cặp cùng nhãn dùng cùng màu, gây mơ hồ role. [Bài báo Alg. 1 và Fig. 4][paper] · [Pair code][pair] · [YAML][pair-config] · [Timestamp/TF][pair-node]

DeepSeek path thực tế tính **vision + MLP projector** trước khi truyền. `DeepSeekVL2Visual.encode_images` chuẩn bị global tile và local tiles, tensor đầu vào logic `[P,T,3,S,S]` với P crops, T tiles mỗi crop. Vision xuất `[P*T,h_v*w_v,d_v]`, projector downsample + project thành `[P*T,h*w,D]`, sau đó flatten thành `[P,T*h*w,D]`. Từ config công khai của large encoder và full-model processor, $S=384$, patch 14, $h_v=w_v=\lfloor384/14\rfloor=27$, $h=w=\lceil27/2\rceil=14$, $d_v=1152$, $D=2560$, $T=1+t_h t_w$. Khi `cropping=False`, thêm một global và một local tile nên mỗi relation mang **392×2560** số. Downstream thêm newline/separator thành **421** image tokens. Đây là phép suy shape từ config và code. Encoder card khai báo base model `deepseek-ai/deepseek-vl2`. API metadata public tại ngày audit cho revision `f363772d1c47f4239dd844015b4bd53beb87951b` của full model. Decoder `generate_caption` reshape về tiles, gọi `encode_conversations_and_features` rồi `prepare_input_embeds_from_feats` để đặt visual tokens vào chuỗi. Vì vậy token layout, projector, model/processor revision, dtype, crop policy, annotation và role order là một signature cần kiểm tra. Một CLIP/SigLIP embedding dùng được cho semantic retrieval riêng. Decoder VL2 đòi đúng projected token sequence. [Vision config][vision-config] · [Processor config][ds-processor-config] · [Extractor][wrappers] · [Decoder][ds-model] · [Projector và token layout][ds-modeling]

Chi phí pair candidates worst case $O(N^2)$. Số inference với cap là $P=m(m-1)/2$, và `include_bbs` đang copy full image cho mỗi cặp, nên metadata/crop processing worst case $O(PHW)$ cả bộ nhớ transient và thời gian trước encoder. Graph-aware thêm depth/mask scans $O(NHW)$, kiểm tra containment $O(NA)$ worst case, scan edges $O(E)$ và tổ hợp $O(m^2)$. Mỗi matrix float32 392×2560 chiếm 4.014.080 bytes, xấp xỉ 3,83 MiB mỗi hướng, trước graph clone, Python lists và JSON. 1.000 lanes đầy đủ cần khoảng 3,74 GiB chỉ cho tensor float32. Lưu ít lanes/chọn keyframe có tác động lớn hơn việc chỉ giảm batch GPU. [Pair extractor][pair] · [Server schema][ds-schemas] · [ROS feature message][feature-msg] · [Edge dtype][spark-edge]

### 6. Edge fusion, hướng và vòng đời

Alg. 4 và Eq. 5 cập nhật $\bar R_{ij}'=(n_{ij}\bar R_{ij}+R_{ij})/(n_{ij}+1)$. Upstream `ImageReceiver::processLabels` dùng `(uint16 panoptic_i,uint16 panoptic_j) → Eigen::MatrixXf`. Mỗi cluster có panoptic ID vote từ vertex, rồi rematch active same-label nodes theo geometry. `MeshSegmenter::updateGraph` bỏ missing edge evidence, cùng panoptic ID hoặc cùng NodeID. Nó tạo một graph edge cho endpoint pair, thông tin hai chiều nằm ở hai lane `relationship_source_target` và `relationship_target_source`, tra qua source NodeID. `setRelationshipProperty` fuse matrix và tăng count theo lane. Graph edge tồn tại với lane ngược rỗng. `AVERAGE` là mặc định. Logic `FIRST/LAST` chỉ nhảy vào nhánh mode tương ứng khi cả hai lane đã có count. `LAST` reset edge khi nhánh đó chạy. Edge commit đi sau bước merge active objects. [Alg. 4][paper] · [ROS matrix decode][receiver] · [Edge setup][mesh] · [Edge implementation][spark-edge] · [Config][mesh-config]

`mergeEdges` đi theo `active_edges[old]`, bỏ self-edge, clone/rekey, fuse cạnh trùng theo count và xóa cạnh cũ. Chỉ mục active được cập nhật theo subject ở bước insert. Cleanup hai chiều và remap archived/backend endpoint qua mọi nhánh chưa được chứng minh. `archiveOldNodes` dọn active sets theo vertex archival và node existence. Spark serializes feature/counter cho mỗi lane và node attributes, nhưng schema feature thiếu model/processor/crop provenance và tuổi evidence. Merge chỉ kiểm shape của matrix khi fuse. Code route trên graph có cluster-pair scan $O(C^2)$ cùng rematching active nodes. Update một lane $O(T h w D)$. Storage worst case $O(EThwD)$ với tối đa hai lanes/edge. NeuSymNav cần index cả hai endpoints, xóa orphan/self-edge, kiểm signature, chuyên biệt loop-closure và alias update, và đánh giá edge rỗng là evidence thiếu. [Merge and cleanup][utils] · [Archive and updates][mesh] · [Serialization][spark-edge]

Quyền diễn giải tách thành bốn kiểu dữ liệu. Visual relation tensor là evidence để hỏi VLM. Output của VLM/parser là verdict và explanation gắn prompt/candidate. Geometric predicates tính từ geometry và tolerance. Future probabilistic beliefs cần observation model và uncertainty. Sparsity của pair graph, stale evidence và label-color collisions đều có thể gây unsupported query. Thiếu evidence chỉ hỗ trợ abstention. [Fig. 4, §§IV-B–C][paper] · [Task judge][nav-vlm]

### 7. Task reasoning và chi phí truy vấn

Prompt service nhận task và room selector. Output tự chọn chế độ object search khi danh sách pair prompts rỗng. `OpenAIPrompter` trả object list và interactions JSON, encode text bằng cùng CLIP. Release lọc interactions theo vocabulary, đổi alias `table→desk`, tạo danh sách embeddings trước khi có thể nối thêm labels từ interaction. Paper nêu o3 cho task reasoning/parser và GPT-4o cho subtask decisor, còn YAML decompose và parser dùng `gpt-4o`. `ObjectSearchModule` bỏ nodes thiếu feature / dưới 20 mesh vertices, lọc room qua parent chain, so cosine $\langle q,f\rangle/(\|q\|\|f\|+\epsilon)$ và lấy mọi score trên 0,65 trong robot config. Sau đó sort objects theo khoảng cách Euclidean tới pose agent. Pair route quét các cặp candidate, chọn edge, deduplicate bằng `minmax(CID_i,CID_j)` xuyên interactions, bỏ cùng tên, rồi lấy matrix đúng lane theo object đầu. Nhánh pair kiểm graph edge tồn tại. Lane riêng có thể rỗng và cần gate trước khi gọi decoder. Chi phí search object $O(QOd)$, xây adjacency pair $O(O^2)$ trong đường relational, cộng sort $O(O\log O)$ và kiểm membership bằng scan ở các pair labels. [Bài báo §IV-C và §V-A][paper] · [Prompt parser][prompter] · [Search][search] · [Cosine][cos] · [YAML][search-config]

`VLMForNavigation.reason_object` gửi subtask kèm màu bbox sang VLM, nhận generation, tùy cấu hình gọi LLM parser qua OpenAI. `_parse_llm_response` kiểm chuỗi chứa `yes` để đánh dấu cả hai ID, nên cần parser typed và verdict `insufficient_evidence` tại điểm nối NeuSymNav. Release client stringify nested float lists và polling HTTP 0,5 s, window 3600 s theo YAML. Server enqueue background job id, tái dựng float32 tensor rồi chạy từng prompt tuần tự và cast bf16 trước decode. `model.py` load toàn checkpoint full qua `from_pretrained` rồi đưa model lên device. Các đoạn inference từ cached feature bỏ qua tính lại vision, và code startup vẫn tải full model. Latency/cost thay đổi theo số pair/subtask, payload, request queue, network, prompt tokens, generation length và số lần OpenAI. Chưa có số liệu API cost/latency dùng được cho NeuSymNav. Cần timeout hữu hạn theo service budget và provenance verdict. Prompt độc lập với control tick.
